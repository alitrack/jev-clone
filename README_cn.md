# jev-clone

本地、**契约兼容**的系统一（System One）决策服务：给一段 `state` + 一组**运行时定义**的类型化问题
（`choice` / `score` / `noul`），返回每个问题的概率分布——**全程不生成一个 token**。

> **当前状态：M0 M1 已落地并过真端点验收**（145+ 单测 / clippy 0 警告 / 契约断言 24/24 /
> 45 条中文题集端到端 + `verify` 复现 0 不匹配）。**M1 的「≥3× 前缀复用」门在共享端点上实测为
> 0.96×、判定未达标**，原因与重述见 [`specs/M1.md`](specs/M1.md) §4.1——不许当成绩念。
> 设计文档见 [`docs/design.md`](docs/design.md)，三份开源蓝本的源码级研究见 [`docs/blueprints.md`](docs/blueprints.md)。

> **独立项目**：与 TypeSafe / Jev 无任何隶属、背书或衍生关系。未使用任何官方权重、数据或代码。

---

## 它是什么

一个把"判断"变成可编程接口的服务：

- 请求里声明 `state`（字符串 / JSON 对象 / 数组）和若干 typed question；
- 服务**一次前向**读出每个选项的概率，返回 `choice` / `probabilities` / `confidence`、
  `score` / `legend` / `noul` 等**与公开 HTTP 契约逐字段同形**的结构；
- 答案被**约束在你给的选项集合内**，调用方永不需要解析自然语言；
- 同一请求的多个问题**共享一次 prefill 并行求值**——多问一个问题的边际成本几乎为零。

## 错误码

两类失败，**永不混用**：

| 状态码 | 含义 | 例子 |
|---|---|---|
| **422** | 请求、或它产生的读数不成立。**改输入**，重试无用。 | 无 questions；选项少于 2 个；选项多于 26 个；档位少于 2 个；prompt 超 token 预算；声明槽位不在读数里（`SlotMissingFromTopK`） |
| **502** | 我们依赖的模型端点失败。**可以重试**。 | 端点返回 HTTP 错误；响应无法解析；响应里没有 `logprobs` |

缺槽位**故意**是 422 而不是 0：模型没有报告概率的选项，其概率是**未知**，把它当 0、或把剩下的重新归一化，都是在一个以校准为卖点的系统里**编数字**。

## 它不是什么

- **不是聊天模型**：不写散文，需要文本生成的任务在构造上就不在范围内。
- **不承诺"不会答错"**：唯一的保证是"输出不会落在选项集合之外"。被约束成选项的答案**依然可能语义上错**——这是厂商自己的失败模式文档里写明的事实，也是本项目把**校准（calibration）**而非 accuracy 当第一指标的原因。
- **不是官方架构/训练方法/数字的复现**：官方闭源、无模型卡，任何参数量或结构的说法都是推测。

## 一句话设计

三份公开复现已把**接口形状**开源，但**没有一份做过校准**，也没有一份面向中文。所以本项目的三个支点是：
① 可验证的校准（公开 ECE / Brier / 可靠性曲线）；② 中文优先的冻结题集；③ 把"同 state 前缀复用"当架构硬指标而不是事后优化。

## 路线图

| 阶段 | 交付 | 验收门 |
|---|---|---|
| **M0** | 契约层 + 槽位校验 + HTTP 服务（无需 GPU） | 公开契约示例请求字段级对齐；槽位校验的失败路径有测试覆盖 |
| **M1** | 批量读数（`prompt` 数组）+ 可复现校准评测 crate | 前缀复用在共享端点上**实测为 0.96×，即该门上未达标**（端点自带的 radix 缓存让基线也拿到了同样的复用）——见 [`specs/M1.md`](specs/M1.md) §4.1，该门已按"缓存归我们管"的后端重述 |
| **M2** | 冻结评测矩阵（中文优先）+ 复现校验 | 一条命令从原始结果重算出报告里每一个数字（**crate + 45 条起步题集已落地；距 150 条目标未达标**，见 [`eval/README.md`](eval/README.md)） |
| **M3** | Route A 头 → Route C LoRA + 温度标定 | 中文题集 ECE ≤ 0.05 且 accuracy 不掉 |
| **M4** | 可选：作为画布/工作流的"机器回答者"接入 | 低置信度自动升级给人 |

## 诚实声明

- 上游服务闭源托管，架构与参数量未公开；本项目**没有**对其权重做任何逆向。
- `confidence` 是我们自己从概率分布算出的统计量。官方不公开公式（并明确说"你不必被我们的定义绑住"）。我们会实现多个候选并用期望校准误差（ECE）挑一个当默认。
- 厂商的 40–200× / 40–400× 提速与降价来自**厂商自建的 workflow 基准**，不得挪用为本项目的数字。
- 评测集以内容 hash 声明；**不同来源的分数禁止合并成一个总分**。
