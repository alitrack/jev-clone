| # | 问题 | 为什么非问不可 |
|---|---|---|
| **R1** | 把译者从「**被评模型自己**」换成与它**无共享失败模式**的第二译源后，中英差异还在不在？<br>（M3：overall zh 0.8378 / en 0.7838，p=0.1338；`rule_application` 0.6757 / 0.4865，p=0.0654） | M3 的英文集是 qwen3.8-27b **自己译的**——**译者＝考生**。这个红利没消掉之前，任何「中文更差/更好」都不可判定。这是 M3 自己写死的停止条件，不是新问题 |

## 2. 关键设计决策（含被否决的备选，理由逐条写）

### D1 第二译源 = **真正的机器翻译引擎（MT）**，不是另一个 LLM

判据：必须与被评模型（8014 上的 qwen3.8-27b）**不共享失败模式**，且**可离线复现**（权重可哈希钉死）。

| 候选 | 判 | 理由 |
|---|---|---|
| 8017 上 NInfer + Qwen3.8-27B | ❌ | **与被评模型同一份权重**（只是 int8+MTP 的推理实现不同）⇒ 译者仍是考生，独立性不成立 |
| Mac 8080 上 Bonsai 27B（2.13 bit 三元） | ❌ | 架构确实不同，但 M3 已实测它在长文本/约束上退化（要求 200 字 → 884 tok；假前提题直接编造参数）⇒ 会引入「译文质量整体下降」这个**新混淆**，把译源效应和量化退化搅在一起 |
| 云端 LLM API（DeepSeek / GPT 类） | ❌ | 花钱、版本漂移、**不可复现**（未来同版本无法保证），且违背「离线可复现」 |
| **NLLB-200-distilled-600M** | ✅ **主选** | 纯 MT 引擎，与 LLM **无共享失败模式**；CPU 可跑；权重可钉 sha256；200 语言含 zh/en。⚠️ 许可 **CC-BY-NC-4.0（非商用）** ⇒ **只作本地评测用，不进任何对外产物**（沿用 M3 已立的许可纪律） |
| MADLAD-400-3B-MT（Apache-2.0）/ OPUS-MT zh-en | 🔶 备选 | 若 NLLB 在 20 条抽检上不合用（§3 S3）则换；换哪一个、为什么换，记进报告 |

### D2 中文侧是基准，**不重译**

`v2` 英文集 = 同一批 `zh` 原件、由 MT 产出 ⇒ **唯一被换掉的变量是译者**。中文集一个字不动，M3 的中文侧数字继续有效。

### D3 两套英文集**都跑、都报**

`v1`（模型自译）与 `v2`（MT 译）并列。两者之差 = **译者敏感度**。**两套方向一致才下结论**（否则见 S2）。

### D4 `rule_application` 扩到 **≥80 条**（现 37）

- **power 依据（照实写，不夸大）**：M3 该层不一致对 9:2（11/37 = 29.7%）。McNemar **精确二项**
  要 p<0.05 需 **≥13 个不一致对**；按同样不一致率反推需 ≈44 条 ⇒ 取 **≥80 条**（1.8× 余量），
  并允许把新增部分**前后各半**做一次方向稳定性检查（两半方向不一致 ⇒ 视为噪声）。
- **⛔ 不许把题写简单**：新增条目必须与既有 37 条**同构**（同为四类任务的 `rule_application` 变体、同难度档）。
  把「选项数分布 / 题型比例 / gold 书写位分布」做进 parity 脚本的**结构统计对照输出**，供复核者自查有没有被偷偷降难度。

### D5 新增题目的作者与译法

- 中文原题**我来写**，**不许让被评模型出题**（否则又变成考生出题）；写法照 `specs/M1.md` 的题面模板。
- 英文侧走 **MT（D1）**，与 `v2` 同一管线、同一参数。
- **`gold` 不许变**：译文下 `gold` 必须仍是唯一正确答案（逐条抽检 + parity 闸门）。

## 3. 停止条件（**先写死，再动手**）

1. **S1 终局**：若 `v2` 下 overall 仍 **p≥0.05**，**且**扩到 ≥80 条后 `rule_application` 仍 **p≥0.05**
   ⇒ **终局结论＝在本仪器、本题集规模下「无证据说明中文更差」**。
   **停**：不再扩题、不再换第三译源（**明确禁止无限升级**）。
2. **S2 译者敏感**：若 `v1` 与 `v2` 给出**方向相反**的结论 ⇒ 结论降级为「**不可判定**」，
   两个 run **都落盘**，**不许只报好看的那套**。
3. **S3 译稿不合用**：20 条抽检里 **>2 条**不可用（意思走形 / 选项不对应）⇒ 换备选引擎并记入报告。
   **⛔ 禁止人工顺手改译文**（人工干预＝新混淆）；单条不可用只允许**整条剔除**，计入 `n_missing` 并**逐条列名**。
4. **S4 规模上限**：新增 ≤60 条（总量 ≤210）。**不许为凑显著性越过此线**。
5. **S5 不做 best-of-N**：不许改 prompt/温度重跑、不许挑好看的 run；不一致**只报差异**。
6. **S6 钱与负载**：不训练、不微调；只做推理（8014 + 本地 CPU/空闲卡）；
   单次批量失败**必须报根因**，**不许换负载重试凑数**（「压测禁替代负载」的老坑）。

---

## 4. 纪律（照抄 M1–M3 已证明的教训）

- **脚本进仓**（`scripts/`）：⛔ 不写内联 `python3 -c` / shell heredoc（本机审批门会拦，别人也读不懂）。
- **逐条交错跑**：`zh-0001 → en-0001 → zh-0002 → …`，不是「先跑完中文再跑英文」——
  共享硬件上的漂移会整段压到后跑的集合上（M1 的 0.96× 假门就是这么来的）。
- **采集口径**：`n_pred` / `n_scored` 必须**等于题集条数**，缺一条就是失败（不是「差不多」）。
- **MT 侧可复现性**：引擎名 + 版本 + 权重 sha256 + 生成参数（beam / 长度惩罚 / max_length）**写进 manifest**；
  下载走 `HF_ENDPOINT=https://hf-mirror.com`、必要时 `HF_HUB_DISABLE_XET=1`。
- **产物命名**：预测/报告文件名带 run 戳（`YYYYMMDDThhmmssZ`）。
- **实时汇报**：长任务分段汇报中间进展（用户会连问「进展？」）；引用命令必须贴真实输出，没跑过写「未实测」。
- **许可**：MT 权重若为 NC 类，**只本地评测用，不进对外产物**；对外引用厂商数字必须写清是哪一份文件。

## 5. 明确不做

- 不做服务、不做自持后端（M2 已停）、不训权重、不做 BP/资源优化；**不动 NPP 仓**。
- **不用云端 API 做译源**；**不合并 `v1`/`v2`/`v3` 数字**；不合并不同出处的厂商数字。
- 不因「样本不够」把题集扩到 500/1000 条（S4 的上限就是这句话的量化）。
- 不写「中文更好/更差」这类**没有 CI 的断言**；不把题集分数用作**模型能力结论**。
