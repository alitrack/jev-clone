## 0. 不变量（M3 不许破坏的东西）

1. **`zh-evidence-v0/v1` 保持字节原样**：它们已冻结、哈希已进 `eval/items/manifest.json`，M1 报告靠它复核。
   M3 的题集**一律新建文件 + 新增 manifest 条目**，绝不就地改旧集。
2. **禁止合并总分**：一切指标按 `source` × `category` 分层上报（`AGENTS.md` 铁律 7 / `specs/M1.md` §6）。
   **中文集与英文集分开报**，禁止算一个「总分」。
3. **冻结面不动**：`trait DecisionBackend`、`Readout` 形状、`/v1/systemone` 字段与错误码、M0/M1 已发布报告。
4. **`verify` 阈值属调用方**（`--tol`，默认仓内常量），报告自报的容差只作为**被审计的主张**；
   **tamper gate 必须每次跑**（改一个数字 + 自报超大容差 ⇒ `verify` 必须非零退出）。
5. **口径权威在 `crates/jev-eval/src/metrics.rs` 的模块文档**，`eval/README.md` 只是散文复述；不一致时以代码为准。
6. **零 GPU 也能跑**：`cargo test --offline --workspace` 必须保持全绿（当前 164 个测试）。
7. **不动 115 GPU1/2**（8014 的 SGLang 常驻），不占用他人作业；本地权重推理只用空闲卡或 CPU。

## 1. 要回答的三个问题（这就是本线的全部理由）

| # | 问题 | 为什么问它 |
|---|---|---|
| **Q1** | 同一模型、**同内容的双语对照**下，中文的准确率与校准比英文差多少？ | 「中文优先」是这个项目唯一存活的角度，但**没有数字就没有主张**。Laya 把 51 语言压成一个宏观可用率（45/51），Khmer 那一行说明这个压缩会藏掉真实的自信错误 |
| **Q2** | 中文上 **confidence 还能不能当门控用**（可靠性曲线是否还压在对角线上）？ | Laya 自己声明非拉丁文字上 *"confidence gating cannot save you"*。这是**有人承认没解决**的问题，且直接决定「能不能把模型判定接进 NPP/cc 的闸门」 |
| **Q3** | 最强的开源替代（Laya 优先）**在中文上的实际水平与校准**是多少？ | 生态里没人公开中文数字；跑一遍比读 README 硬。**结论无论正负都要落盘**（若 Laya 中文很好，我们的缝就没了，那是必须公开的结论） |

## 3. 停止条件（**先写死，再动手**）

> ⚠️ **已知混淆（写进报告局限，不许省略）**：英文对照集由**被评模型自己**（8014 上的 qwen3.8-27b，经 sigil 驱动）翻译。
> 译者与考生同一 ⇒ 英文侧可能吃到**风格/词汇偏好**的红利。
> 因此：**若结果显示英文更好，不得直接断言「中文能力弱」**，必须先做稳健性复核——用**第二个翻译源**（不参与评测的模型）
> 重译同一批题，看差异是否仍在。**这一步写进 M3-4 的交付要求。**

1. **Q1 证伪 ⇒ 停**：若中英 **ECE 差 < 0.02** 且分 `category` 的**排序一致**（秩相关 ≥ 0.8），
   ⇒「中文特有的校准问题」不成立 ⇒ **停止该方向并在报告首段写明**（不许换个说法继续找题目）。
2. **Q3 证伪 ⇒ 停**：若 Laya 中文 `accuracy ≥ 27B` **且** `ECE ≤ 27B`，
   ⇒「开源替代中文不行」不成立 ⇒ 停止，并把该结果作为**公开结论**落盘（这比继续做更重要）。
3. **规模不上调**：150 条即冻结规模。**不许**因为「样本不够」而把题集扩到 500/1000 条来凑显著性——
   分层的置信区间照实报（n=38 的类别 CI 很宽，这是事实不是缺陷）。
4. **不做第二轮调参**：不一致时**只报差异**，不许改 prompt/温度再跑一次挑好看的数字（不做 best-of-N）。
5. **预算**：不训练、不微调；115 上只做推理（8014 端点 + 本地小权重）；单次批量跑失败**必须报根因**，不许换负载重试凑数。

## 4. 纪律（照抄 M1/M2 已证明的教训）

- **题集翻译**（M3-1）：⛔ 不许改变答案——`gold` 在译文下必须仍是正确答案；`state` 自足、**不新增事实**；
  选项数与标签一一对应；**槽位单 token 约束要在英文侧重验**，某条在英文下不成立就标
  `en_infeasible` + 原因（**不许静默改 gold 或截断**）。输出只写约定的一个文件，禁建目录/链接。
- **端点容量**：8014 是共享 SGLang（他人在用），**先量空闲延迟再定并发**；worker 一律
  **串行 + 重试 + 断点续跑**；sigil 的流空闲超时硬编码 120 s 不可调 ⇒ 单个 worker 任务切小。
- **配对跑法**：两集**逐条交错**（zh-0001 → en-0001 → zh-0002 → …）而不是「先跑完 150 中文再跑 150 英文」——
  共享硬件上的漂移会整段压到后跑的集合上（M1 的 0.96× 假门就是这么来的）。
- **采集口径**：`n_pred` / `n_scored` 必须等于题集条数，缺一条就是失败（不是「差不多」）。
- **脚本进仓**：驱动/汇总脚本落 `scripts/`，不写内联 heredoc / `python3 -c`（本机审批门会拦，别人也读不懂）。
- **实时汇报**：长任务分段汇报中间进展（用户会连问「进展？」）。

## 5. 明确不做

- 不做服务、不做自持后端（M2 已停）、不训权重、不做 BP/资源优化。
- 不把 Jev 云接进 NPP/cc 执行路径；不动 NPP 仓。
- 不用题集分数做**模型能力结论**（全为自撰题，只作**同一口径下的相对对照**）。
- 不写「中文更好/更差」这类没有 CI 的断言；不合并出处不同的数字。
