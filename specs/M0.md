# M0 任务书 —— worker 契约（2026-09-19）

本文件是 M0 阶段实现的**唯一权威规格**。实现前先读 `docs/design.md`（项目定位）
与 `docs/blueprints.md`（三份蓝本源码级研究）。

## 0. 不可违反的不变量

1. **答案被约束在调用方给的选项集合内**。我们只承诺这一点，绝不承诺"答案正确"。
   任何文案、注释、README 都不得写"不能幻觉/不会出错"。
2. **不生成文本**。读的是一个位置的 top-k log-prob 分布，生成的唯一 token 只用于取分布，
   其文本被丢弃，**永不解析**。
3. **题目 ID 不进 prompt**（只用于应答索引）。
4. **同一请求内各题相互独立**（A 题的答案不得进入 B 题的上下文）。
5. **槽位校验失败 / 读不到槽位 = 报错**，绝不静默按 0 分或按先验答题。
6. **不截断**。prompt 超预算直接报错（`CoreError::PromptTooLong`），不做静默裁剪。

## 1. 已实测的端点事实（探针结果，2026-09-19，务必按此实现，勿凭想象）

| 探针 | 结果 |
|---|---|
| `POST http://10.10.10.115:8014/v1/completions` + `{"max_tokens":1,"temperature":0,"logprobs":10}` | **可用**。返回 `choices[0].logprobs.top_logprobs[0]` = `{"yes":-0.229,"Yes":-1.854,"**":-3.854,...,"no":-5.354,...}`（token 文本 → logprob），并带 `usage.prompt_tokens` |

| `POST /tokenize`（与 `/v1/tokenize`） | **可用**，返回 `{"tokens":[15666,25,198,32],"count":4,"max_token_len":262144}`。`"Answer:\n"` = `[15666,25,198]`；追加 `A`→`[...32]`、`B`→`[...33]`、`Z`→`[...57]` ⇒ **字母是单 token 且边界稳定**（prompt 段未重切） |

## 3. Worker A —— jev-core 实现要求

### A1 `render_question(state, question, question_id) -> Result<RenderedQuestion, CoreError>`
- 统一骨架（eval 会 hash prompt，形状必须稳定）：
  ```
  State:
  <render_entry(state)>

  Question:
  <render_entry(instructions)>

  <题型专属段>

  Answer:
  ```
- `render_entry`：字符串按原样；对象/数组用 `serde_json::to_string_pretty`；`null` → `"null"`。
- **choice**：题段为 `Choose exactly one option.\nOptions:\n- A: <label>`，每项一行；
  `criteria` 的 value 非 null 时追加 ` — <description>`（em dash 前后各一空格）。
  slot→value 映射 = criteria 的 key（按 `BTreeMap` 字典序，稳定即可）。
  选项数 <2 → `TooFewChoiceOptions`；>255 → `TooManyChoiceOptions`。
- **score**：题段为 `Choose exactly one level.\nLevels:\n- A: 0: <level0>`（按 0..n-1 顺次），
  描述里的对象/数组同样走 `render_entry`。slot→value = `"0"`,`"1"`,…（档位序号的十进制字符串）。
  档位数 <2 → `TooFewScoreLevels`。
- **noul**：题段为 `Answer yes or no.`；若有 criteria，把 true/false 的说明以
  `\n- yes: <...>` / `\n- no: <...>` 追加。slot→value = `"true"`（A）、`"false"`（B）。
- 选项数 >26 时（choice 允许到 255）：字母不够用 → 在报告里说明你的处理（建议：M0 直接返回
  错误或改用双字母槽位；**必须显式处理，不许静默截断**）。
- `question_id` 仅用于错误信息。

### A2 `verify_slots(tokenizer, prompt, count) -> Result<SlotSet, CoreError>`
- 逐字母校验：`encode(letter)` 必须恰好 1 个 token（否则 `SlotNotSingleToken`）；
  `encode(prompt + letter) == encode(prompt) ++ [slot_id]`（否则 `SlotBoundaryChanged`）；
  所有 slot 的 `token_id` 互不相同（否则 `SlotCollision`）。
- `token_texts[i]` = 字母本身（`"A"`），读出头会额外容忍前导空格变体。
- 返回的 `SlotSet.letters` 顺序 = 选项顺序。

### A3 `softmax`, `score_expectation`, `confidence_from_probabilities`
- `softmax`：数值稳定（减 max）；**空输入或全 `-inf` → 返回等概率**（不许 NaN）。
- `score_expectation(p) = Σ i·p_i`。
- `ConfidenceMode::NormalizedEntropy` = `1 - H/log(n)`，`H = -Σ p log p`（`p>0` 才计入）；
  `n==1` → 1.0；结果必须落在 `[0,1]`（浮点误差夹紧）。
  `Margin` = `p(top1) - p(top2)`（n==1 → `p(top1)`）。`Top1` = `p(top1)`。

### A4 必写测试（`crates/jev-core/tests/`，用 `FakeTokenizer` 实现 `SlotVerifier`）
1. 三种题型的 render 结果**逐字符**断言（贴出实际字符串，别只断言 contains）。
2. choice 选项 <2 / >255 各报对应错；score 档位 <2 报错。
3. `verify_slots` 三个失败分支各一例（多 token 槽、边界改变、碰撞）+ 一个成功例
   （用真实 id：prompt=`"Answer:\n"`→[15666,25,198]，A→32，B→33）。
4. `softmax` 归一化（和=1±1e-9）、极值不 NaN、等概率输入 → 1/n。
5. `confidence` 三模式：one-hot → 1.0；均匀分布 → 0.0；`Margin` 单调性。
6. `score_expectation` 对 one-hot 第 k 档 = k。

## 4. Worker B —— jev-backend / jev-server 实现要求

### B1 `OpenAiCompatBackend::new` + `token_logprobs(prompt, top_k)`
- `POST {base_url}/completions`，body 见下表；**不要**走 chat 接口。
  ```json
  {"model":"<model>","prompt":"<prompt>","max_tokens":1,"temperature":0,"logprobs":<top_k>}
  ```
- 解析 `choices[0].logprobs.top_logprobs[0]`（对象：token 文本 → logprob）。
  该字段为 `null`/空 → `BackendError::NoLogprobs`；HTTP 层非 2xx → `BackendError::Http`（带上
  body 前 500 字符，便于识别 `logprobs_not_supported`）；JSON 走不通 → `BackendError::Decode`。
- `top_k` 建议 ≥ 选项数+5（调用方决定），实现里不要偷偷加大。
- `usage.prompt_tokens` 填进 `Readout.prompt_tokens`，`completion_tokens` 填 1。
- 超时：connect 10s / total 由 `cfg.timeout_secs`。

### B2 `Readout::slot_logprob(slot_token)`（在 `lib.rs` 的 TODO 处实现）
- 匹配规则：`strip()` 后等于 `slot_token` 的 key **全部**纳入（`"A"` 与 `" A"` 是同槽位的两种
  表面形式）；**logsumexp 相加**，不得取最大值。返回 `None` 表示 top-k 里没有该槽位。

### B3 `HttpTokenizer`
- `try_encode`：`POST {base}/tokenize`，非 2xx 或解析失败则回退 `{base}/v1/tokenize`；
  返回 `tokens` 数组；带缓存（`Mutex<HashMap>`）。
- `prefetch(texts)`：并发拉全部需要的编码（`futures`/`join_all` 或顺序皆可，顺序即可）。
- `encode`：缓存命中返回；缺失则 `panic!` 并说明"必须先 prefetch"。
- `decode_token`：M0 无 detokenize，返回能判定时的大写字母，否则 `"<unk>"`（仅诊断用）。

### B4 `jev-server`
- `main.rs`：按 `main.rs` 顶部注释的环境变量装配（已写好大部分，补全即可）。
  启动时**必须**做一次自检：用 `HttpTokenizer` 校验 `"Answer:\n"` + `A` 的槽位假设，
  失败则拒绝启动并打印清晰错误（fail-fast，别带着坏 tokenizer 上线）。
- `api.rs::systemone`：
  1. `questions` 为空 → 422 `CoreError::NoQuestions`。
  2. 每题：`render_question` → `prefetch`（prompt 与 prompt+letter）→ `verify_slots` →
     `backend.token_logprobs(prompt, top_k)`（`top_k = max(选项数+5, 10)`）→ 每个 slot 取
     `slot_logprob`，任一为 `None` → `CoreError::SlotMissingFromTopK` → 502/422 报错 →
     `softmax` 得到概率（和必须 =1±1e-6，否则 `CoreError::Unnormalized`）。
  3. 组装 Answer：choice = argmax 的 label + `probabilities`（label→概率）+ confidence；
     score = `score_expectation` 作为 `score`、`legend` = 档位序号→档位描述文本、
     `probabilities` = 序号字符串→概率、confidence；noul = `{"noul": P(slot A 即 yes)}`。
     概率**保留 6 位小数**（`(x*1e6).round()/1e6`），避免 0.30000000000000004 之类的脏值。
  4. `usage`：`input_tokens` = 各题 `prompt_tokens` 之和；`output_tokens` = 题数 ×1。
  5. `model` 取 `backend.model_name()`。
- 错误映射：`CoreError` → 422，`BackendError` → 502（`api.rs` 里的 `ApiError` 已经定好形状）。
