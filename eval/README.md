# `jev-eval` — 校准评测的口径与用法

本目录是 M1-2 的落点：把「答案对不对」升级成「答案对不对 **以及它自己知不知道自己对不对**」。

**口径的最终权威是 `crates/jev-eval/src/metrics.rs` 的模块文档**；本文件是它的散文复述。
两者不一致时，以代码为准，本文件算 bug（`metrics.rs` 第 3 行就是这么约定的）。

---

## 1. 冻结题集 `eval/items/*.jsonl`

一行一个 JSON 对象；`#` 开头与空行忽略。字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | ✓ | 题号，评测与预测文件靠它对账 |
| `category` | ✓ | 分层键之一，见下 |
| `source` | ✓ | 题集来源标识（也是分层键，**永不合并**） |
| `state` | ✓ | 模型看得到的材料（中文，自足） |
| `question` | ✓ | `jev-core` 契约里的 `Question`（`choice` / `score` / `noul`），JSON 原样 |
| `gold` | ✓ | 标准答案：`choice` 为选项标签；`score` 为档位索引（整数）；`noul` 为 `true`/`false` |
| `positive` | 可选 | 二值化时哪个槽位是正类（只影响 `brier_binary`）。**没有缺省值**：不写就不参与 `brier_binary`（`n_binary` 会小于 `n_scored`），`noul` 由契约固定为 `"true"`。口径以 `metrics.rs` 为准（见本文件开头） |
| `provenance` | 可选 | 这道题为什么这么判——写给复核的人看，**必须能由 `state` 推出** |

`question` 的三个变体以 `crates/jev-core/src/contract.rs:30-56` 为准，三处形状各不相同：

- `choice` —— `criteria: BTreeMap<String, Value>`，**槽位 A/B/C 由键的码点序决定**（不是书写序）。
  这是"翻译把答案槽换掉"那个坑的根源，也是 `check-en-parity.py` 逐条比 `slot_index` 的原因；
- `score` —— `criteria: Vec<Entry>`，**有序**，就是档位文字；
- `noul` —— `criteria: Option<NoulCriteria>`，即 `{"true": …, "false": …}`，**可以没有**。
  本集 32 条 noul 里 24 条写了 `"criteria": null`、8 条根本不写这键——两者在 Rust 里都是 `None`，
  所以**任何键集合比较都必须把 `null` 当作缺省**。（曾有闸门把"noul 带 criteria"当错误，
  假失败了一整块；见 `manifest.json` 与 M3 记录。）

四类（`category`，Q2 的能力拆分）：

- `evidence_judgment` — 材料支持不支持某个断言；
- `rule_application` — 把规则套到事实上；
- `candidate_selection` — 在若干候选里选最合适的；
- `missing_evidence` — 判断某关键材料是否缺失。

题集是**冻结**的：`eval/items/manifest.json` 记录文件 sha256 与条数，
`run --manifest` 在哈希不符时**拒绝计算**。改题集必须显式改 manifest（有意为之的动作），
不许悄悄改。

  纯函数式合并（按 id 排序、重复 id 直接失败），因为冻结点必须字节可复现：手改一行就是"悄悄不再可复现"的开始。

## 2. 三个子命令

```bash
# 服务端答案 → 预测行（predictions JSONL）
jev-eval import --items eval/items/zh-evidence-v1.jsonl \
                --answers eval/runs/<date>-answers.json \
                --out     eval/runs/<date>-predictions.jsonl

# 出报告（可加 --manifest 做哈希闸门，--out/--md 落盘）
jev-eval run --items eval/items/zh-evidence-v1.jsonl \
             --predictions eval/runs/<date>-predictions.jsonl \
             --manifest eval/items/manifest.json \
             --out eval/runs/<date>-report.json --md eval/runs/<date>-report.md

# 复现校验：从原始证据重算报告里每一个数字并逐项比对（阈值由 --tol 给出，默认 1e-12）
jev-eval verify --items eval/items/zh-evidence-v1.jsonl \
                --predictions eval/runs/<date>-predictions.jsonl \
                --report eval/runs/<date>-report.json
```

`--answers` 的形状就是 `SystemOneResponse`：`{"model"?, "answers": {"<id>": Answer}, "usage"?}`。
`import` 会把**没有答案**的题写成 no-answer 行并以警告列出（覆盖度不许被藏起来），
并额外报告「服务端自己的 decision 与它自己分布的 argmax 不一致」的题目——这是免费的契约自检。

## 3. 指标口径（冻结）

- **predicted slot** = 概率向量的 `argmax`，平局取题目声明的槽位顺序里更靠前的那个；
  没有概率向量的行取预测文件里的 `label`。
- **准确率** = 预测正确的行数 / 有预测的行数。
- **平衡准确率** = 各**实际出现过的 gold 类**的召回率的平均；没有 gold 的类被排除
  （这是 SemIf `evaluate.py` 的约定，即 macro-recall）。类别多于两类时含义不变。
- **NLL** = 有评分行上 `-ln(max(p_gold, 1e-12))` 的平均。
- **Brier 两种都给**（选项多于两个时「Brier 分数」是有歧义的）：
  - `brier_multiclass` = `Σ_k (p_k − 1[gold == slot_k])²` 的平均；
  - `brier_binary` = 仅在有 `positive` 的行上 `(p_positive − 1[gold == positive])²` 的平均，
    `n_binary` 记录参与行数；
  - 两槽位时二者精确相关：`multiclass = 2 × binary`（有测试断言这一点）。
- **confidence** = `max(p)`，即预测槽位背后的概率质量。
- **ECE** = `Σ_b (n_b / N) · |acc_b − conf_b|`，`bins` 个等宽箱；
  箱号 `min(bins−1, floor(conf · bins))`，所以 `conf == 1.0` 落在最后一箱而不溢出。
  `N` 为有评分行数。
- **可靠性曲线** = ECE 所累加的每箱 `(lower, upper, n, mean_confidence, accuracy)`；空箱省略。

没有概率向量的行计入 `n_items` / `n_missing` 与准确率，但**不参与** NLL / Brier / ECE；
`n_scored` 明确给出真正参与的行数。

## 4. 必读的两条诚实性约定

1. **覆盖度不许被藏。** 缺答案的行、没有概率的行都在报告里单列计数（`n_missing` / `n_scored` /
   `n_binary`），且 `import` 会把缺答案的题逐条列名。
2. **报告里的每个数字都能重算。** `verify` 从题集与预测文件重算全部指标并与报告逐项比对。
   **审计阈值属于调用方**：`--tol`，默认 `1e-12`；报告里自报的 `verify_tolerance` 是被比较的**主张之一**，
   报得比我们松就记 mismatch。2026-09-19 之前 `verify` 反过来从被审计的报告里读阈值，于是「改掉 ECE +
   自报 `verify_tolerance: 1e9`」就能打印 `0 mismatches` 并 exit 0 —— 端到端脚本的第 6 步
   （`scripts/tamper-report.py`）就是这一步的否证测试，它必须以非零退出才算通过。报告不可复现 = 报告作废。

### 8.3 中英对照结果：整体不显著，差异只可能藏在 `rule_application`

| en | 148 | 0.7838 | 0.8923 | 0.4385 | 0.2694 | 0.0870 |

配对分析（`scripts/pair-diff.py`，逐条配对，n=148；2 条英文条目后端读不出概率，已列名退出配对）：

| 分层 | n_paired | zh acc | en acc | 只有 zh 对 | 只有 en 对 | McNemar p |
|---|---|---|---|---|---|---|
| **overall** | 148 | 0.8378 | 0.7838 | 15 | 7 | **0.1338** |
| `candidate_selection` | 38 | 1.0000 | 0.9737 | 1 | 0 | 1.0000 |
| `evidence_judgment` | 38 | 0.8158 | 0.8421 | 2 | 3 | 1.0000 |
| `missing_evidence` | 35 | 0.8571 | 0.8286 | 3 | 2 | 1.0000 |
| `rule_application` | 37 | 0.6757 | 0.4865 | 9 | 2 | 0.0654 |

**判读（谨慎到底）**：整体差异**不显著**（22 条不一致，净差 8，p=0.13）⇒ **没有任何证据支持
"中文更差"或"中文更好"**。唯一方向一致的层是 `rule_application`，而它的方向是**英文更差**
（0.676 → 0.487），与"中文难"相反；p=0.065 未达显著，且 4 个分层各测一次未做多重比较校正，
**只能当线索**。中文本轮 0.8400 与 M1 的 0.8400 完全相同（126/150），说明仪器稳定。

⇒ 对 M1 那个弱层的正确读法：**它更像"两种语言都难"的任务难度地板，而不是中文的锅**。

### 8.4 置信门控曲线（`scripts/gate-curve.py`）

门控的价值不在 ECE，而在**拒掉一部分之后剩下那部分的正确率**：

| 预测集 | 全量 acc | 阈值 0.85（覆盖率→覆盖内 acc） | 阈值 0.90 | 阈值 0.95 | 50% 覆盖率下 |
|---|---|---|---|---|---|
| qwen3.8-27B（中文） | 0.8400 | 60.0% → **0.9444** | 50.0% → **0.9600** | 30.0% → 0.9556 | **0.9600** |
| qwen3.8-27B（英文） | 0.7838 | 55.4% → **0.9634** | 46.6% → **0.9710** | 23.0% → **1.0000** | **0.9595** |
| Laya-multilingual（中文） | 0.5467 | 33.3% → 0.6000 | 22.0% → 0.5455 | 12.7% → **0.5263** | 0.5867 |
| Laya-english（读中文） | 0.4533 | 14.0% → 0.4762 | 10.0% → 0.5333 | 5.3% → 0.6250 | 0.5600 |

**中英两侧门控同样有效**（50% 覆盖率下 0.9600 / 0.9595）⇒ 门控能不能用**取决于模型是否
在分布内，不是语言的性质**。Laya 那一行是反例：阈值推到 0.95 只剩 12.7% 的答案，
正确率反而从 0.547 **掉到 0.526**，被拒的条目里还有 40–48% 其实是对的。

### 8.5 对标：Laya（外部 322M 校准模型）在中文上的读数

同一份中文冻结集、同一套指标（`scripts/accept-m3-laya.sh`；其概率向量是 4 位小数舍入，
先用 `scripts/normalize-answers.py` 显式归一化以满足契约的 `Σp = 1 ± 1e-6`，
逐字原件与偏差记录都留档，150 条里 20 条被重标定、最大偏差 1e-4 = 纯舍入）：

| 预测集 | n | acc | bal_acc | nll | ece | 平均最大概率 |
|---|---|---|---|---|---|---|
| qwen3.8-27B（中文，本节同次运行） | 150 | 0.8400 | 0.8802 | 0.4035 | **0.0481** | 0.833 |
| Laya-multilingual（中文） | 150 | 0.5467 | 0.5837 | 1.0932 | **0.2212** | 0.738 |
| Laya-english（英文 checkpoint 读中文） | 150 | 0.4533 | 0.5539 | 0.9788 | **0.1503** | 0.603 |
| 常数基线 `slot-prior` | 150 | 0.4800 | 0.4400 | 0.8259 | **0.0000** | 0.480 |

**一手交叉验证**（这是我愿意给这条数字背书的原因）：我实测 Laya 中文 ECE = 0.2212，
而厂商自己的 `BENCHMARKS.md`（GitHub，51 语言逐语言表）给 `zh-CN` 的 ECE 是 **0.212**、
`zh-TW` 0.327；同文件里 in-task 总体 ECE 是 **0.030**、zero-shot 是 **0.204**。
⇒ 我这条仪器在厂商自己的一手数字上对得准；**中文校准比训练内差约 7 倍，是厂商数据也承认的**。

**必须挂的边界**：本集是自撰的推理型题（证据判读/规则应用/候选选择），而 Laya 是 322M 编码器 +
类型化头、**一次前向、无推理步骤**，其自报基准是 MASSIVE 意图/XNLI 等另一个任务族。
所以正确表述是"**在这台仪器、这个任务族里 Laya 的中文读数如此**"，不是"Laya 中文能力差"。
另外一个实务坑：Laya 返回的 `confidence` 字段**不等于最大概率**（第 1 条概率 0.67/0.33 而
它自报 `confidence` 0.0815）——我们的指标只用分布、不用这个字段，但拿它做门控会踩坑。

### 8.6 这一节必须一起念的一切

1. **ECE 必须与 acc/NLL 并读**：常数策略 0.0000、英文 checkpoint 0.150 比多语 0.221"更好"
   而正确率更低（摊平就 ECE 低）。任何"校准好"的断言都要同时给出 acc。
2. **不得断言中文更弱**：整体 p=0.13，唯一有方向的层是英文更差，且翻译者是**被评模型自己**
   ——须换第二翻译源复核后才可重新讨论。
3. **门控是模型性质、不是语言性质**：同一阈值下 qwen 中英都到 0.96，Laya 两种 checkpoint
   都到不了 0.62。
4. **单次采样、无置信区间；2/150 英文条目读不出概率**（后端 top-100 logprobs 缺该槽位字母），
   层间 1–2 条差距不可解释。§5 已同步更新仍未做的部分。
